영상이 뒤집혀 있으면 기존 Mac의 180° 회전과 같은 옵션을 사용합니다:


## 1 → 9 → 4

1. 필요하면 **전체 화면**을 먼저 누릅니다. **1 → 9 → 4 시작**, 눈 영상 확인 완료를 누릅니다. 눈 모델이 준비될 때까지 좌우·상하 점을 따라 봅니다.
2. **1단계:** 중앙 점을 1.6초 바라봅니다. 기존 Orlosky와 같이 안내용 정면 고정이며, 새 영점 변환을 추가하지 않았습니다.
3. **2단계:** 3×3 9점. 각 점에서 0.9초 대기 후 1.2초 수집합니다. 유효 12프레임 이상, raw 중앙값 기준 거리의 90백분위 ≤0.08이어야 합니다. 6항 2차 다항식으로 화면 좌표를 맞춥니다.
4. **3단계:** 학습에 사용하지 않은 대각선 내부 4점 `(0.3,0.3)`, `(0.7,0.3)`, `(0.3,0.7)`, `(0.7,0.7)`을 검증합니다. 기존 임계값인 정규 좌표 거리 ≤0.12를 네 점 모두 통과해야 완료합니다. 화면에서는 네 점의 오차를 모두 기록한 뒤 통과 여부를 표시합니다. 실패 시 9점부터 재보정하며, 유효 프레임이 부족하면 같은 점을 재시도합니다.
5. 완료 후 노란 시선 커서를 확인합니다. 화면 크기 변경, 카메라 재연결, 새로운 보정은 기존 보정을 무효화합니다.

현재 `exhibition/gaze.py`는 3점 검증이며 오래된 운영 화면은 중앙 한 점 검증입니다. 여기에서는 요청한 4점으로 바꿨습니다. **Orlosky가 기본**이고 PuRe+pye3d, Pupil Labs 2D/3D, ElSe, 기존 Orlosky를 선택할 수 있습니다. `--engine orlosky`로 이전 기준선을 실행할 수 있습니다. 2D 입력은 동공 영상 좌표이며 물리적인 3D 시선으로 기록하지 않습니다. 3D 초점거리 기본 560px는 실측값이 아니므로 해당 옵션은 실험용입니다. 3D는 눈 모델 준비 시간·표본 수·관측 범위를 확인한 뒤 보정을 허용하며, 이는 정답 대비 정확도를 보장하는 검사가 아닙니다.

## 미리보기와 동공 설정

연결됐을 때 **영상 피드 끄기/켜기**는 안내·보정 미리보기만 숨깁니다. 카메라 캡처, 추정, 로그, 녹화와 IR LED는 계속 작동합니다. 연결되지 않았을 때 같은 버튼은 **카메라 연결 새로고침**으로 바뀌어 USB 장치를 다시 검색합니다. 진행 중 보정 또는 영상 녹화 중에는 재연결을 거부해 자료 손실을 막습니다.

눈 영역 지정 후 미리보기에서 드래그하거나 왼쪽·위·오른쪽·아래 비율을 키보드로 입력하고 **설정 적용**을 누르세요. 아홉 방향을 볼 때도 동공 전체가 영역 안에 있어야 합니다. 홍채를 따라가면 최대 지름을 줄이되 실제 동공 장축보다 작게 제한하지 마세요. 지름은 확대된 640×480 처리 영상 기준이며 320×240 센서에 없는 세부 정보를 늘려 주지는 않습니다. PuRe/ElSe의 크기 제한과 Pupil Labs의 명암 범위를 비교할 수 있습니다. 기존 Orlosky는 영역 제한을 지원하지 않아 전체 영역만 허용합니다.

기존 Orlosky 모델 고정 방식은 기준선에 남겼습니다. pye3d는 9점·4점 수집 중 눈 모델을 고정하고 완료 후 적응을 재개합니다. 눈에 대한 카메라 이동 대응을 시험하기 위한 옵션이며 머리와 화면의 상대 움직임은 별도 기준 영상/자세 정보 없이 완전히 보정할 수 없습니다.

## 로그와 영상 기록

**로그 + 영상 함께 시작 → 사용자가 1→9→4 진행 → 함께 종료 → 기록 ZIP 다운로드** 순서로 사용하세요. 기록 버튼은 보정 중 안내 패널에도 있습니다. 로그와 영상은 각각 시작/종료할 수 있고, 하나라도 기록 중이면 같은 기록 묶음을 사용합니다. 둘 다 종료한 뒤 다시 시작하면 새 폴더를 만듭니다.

보정 시작/취소/재시도/초기화는 기록을 지우거나 종료하지 않습니다. 페이지를 새로고침해도 서버의 기록은 계속되므로 버튼 상태를 확인하고 종료하세요. 서버를 정상 종료하면 열린 로그와 AVI를 닫습니다.

파일은 `camera_accuracy/recordings/<UTC시각-식별자>/`에 남으며 Git에서 제외됩니다. 별도 계정이나 업로드 없이 로컬에 저장합니다. 다운로드한 ZIP 하나를 전달하면 분석에 필요한 로그와 영상 시각을 함께 확인할 수 있습니다.

| 파일 | 내용 |
|---|---|
| `metadata.json` | 카메라·설정·코드 SHA-256, 초기 상태와 모델, 보정점, 기록 구간 시작/종료 시각 |
| `tracking.jsonl` | 처리한 프레임마다 타원/방향/품질, 실패 프레임, 필터 전후 좌표, 눈 모델 고정 상태, 보정 명령/오류/결과, 프론트 목표 좌표/단계/시각 |
| `camera-01.avi` 등 | 카메라가 반환한 영상. 크롭/180° 회전/초록 타원 적용 전의 입력을 MJPEG로 저장. 음성 없음 |
| `camera-01-frames.jsonl` 등 | 영상 프레임 번호(0부터), 처리 `seq`, 파일 이름, 캡처 반환·처리 시각 |

AVI는 처리 FPS를 재생 FPS로 사용하므로 실제 간격이 들쭉날쭉하면 재생 시간이 실제 실험 시간과 다를 수 있습니다. 정확한 시간 분석은 JSONL의 시각을 사용합니다. 녹화 대상은 **추정에 사용한 프레임**이며 센서가 출력하는 모든 프레임을 녹화하는 기능은 아닙니다. 입력 픽셀은 그대로 사용하지만 MJPEG는 손실 압축이므로 센서 RAW/무손실 영상으로 해석하지 마세요. `capture_return_monotonic_s`는 OpenCV가 프레임을 반환한 시각이며 실제 노출 시각이 아닙니다.

## 간단한 진단 JSON

기존 **진단 JSON 저장**은 간단한 메모리 보고서입니다. 실패 시 취소 전후, 새 보정 시작 전에 저장하세요. 다음 보정은 이 메모리 보고서의 이전 시도를 지웁니다. 위에서 시작한 디스크 로그/영상은 계속 유지됩니다.

JSON에는 성공·실패·재시도를 모두 포함합니다:

- `attempts`: 목표 좌표, raw 샘플, 수집 시간, 유효/전체 프레임 수, raw 흔들림.
- `frames`: 유효 프레임의 방향 벡터, 동공 타원, 형태 품질, 눈 중심, 적응 구 반경, 처리 시각. 센서 노출 시각은 아닙니다.
- 검증 시 `predicted`: 필터·클리핑 전 예측 좌표, `delta`, `error_norm`, `error_px`.
- `model`: 정규화와 회귀 계수, 학습 최대 오차. 취소 후에도 마지막 모델과 뷰포트는 보고서에 유지됩니다.
- `design_condition`: 현재 9점이 유지될 때의 회귀 설계행렬 조건수. 취소 후에는 null입니다.

`error_px`는 보정 뷰포트의 **CSS 픽셀 거리**입니다. `error_norm=0.12`는 정확도 88%라는 뜻이 아닙니다. 시각각 오차는 화면의 실제 크기·관찰 거리·눈 위치를 측정해야 계산할 수 있으므로 표시하지 않습니다. 현재 FPS와 ms도 전체 눈 움직임→화면 지연을 측정한 수치가 아닙니다.
