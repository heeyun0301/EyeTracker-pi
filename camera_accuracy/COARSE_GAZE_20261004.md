# 큰 영역 우선 보정 (`--coarse`) — 2026-10-04

목표는 1px 정밀도가 아니라 **보정이 통과되고, 큰 범위에서 시선을 따라가는 느낌**을 주는 것입니다.
`deepvog-verified`(동공 오검출 차단) 위에 보정·출력 쪽 옵션을 추가했습니다. 기본값은 기존과 같고, 옵션을 켤 때만 바뀝니다.

```bash
# 추천 시작점: 3열×2행 영역, 640×480 캡처, DeepVOG 검증
bash camera_accuracy/start.sh --engine deepvog-verified --coarse --grid 3x2 --capture-size 640x480
```

## 바뀐 것

| 옵션 | 내용 | 근거 |
|---|---|---|
| `--mapping affine` | 화면 매핑을 2차(6항)에서 1차(3항)로. | 실제 기록의 한 점 생략 예측 오차가 가로 0.120→0.085, 세로 0.345→0.237로 줄었습니다. 매핑 함수 연구(Cerrolaza 외, ACM TOCHI 2012)도 항을 늘린다고 정확도가 크게 오르지 않는다고 보고했습니다. |
| `--validation region --grid 3x3` (또는 `3x2`) | 검증 기준을 "거리 0.12"에서 "해당 점을 중심으로 한 화면 영역(1/열 × 1/행) 안에 들어오는가"로. 3×3이면 가로·세로 각 ±0.167, 3×2면 세로 ±0.25입니다. | 목표가 큰 영역 단위이므로 기준도 그에 맞춥니다. 시선 입력 연구(Feit 외, CHI 2017)는 정확도가 사람·화면 위치별로 크게 다르고 가장자리·아래쪽에서 나빠지므로, 목표 크기를 그만큼 크게 잡으라고 권합니다. |
| `--bottom-row 0.8` | 9점 중 아래 줄을 y=0.9에서 0.8로. | 실제 기록에서 아래 줄을 볼 때 동공 세로 위치가 가운데 줄과 거의 같았습니다(윗눈꺼풀 가림 의심). |
| 9점 중 1점 제외 (`--coarse`에 포함) | 나머지 8점이 서로 맞는데 1점만 어긋나면 그 점만 빼고 맞춥니다. 2점 이상이면 그대로 실패합니다. | 실제 기록에서 영역 기준 3×2는 1점(3번 목표)만 빼면 학습을 통과했습니다. |
| `--capture-size 640x480` | 카메라 요청 해상도. GC0308은 VGA 센서입니다. | 아래 시뮬레이션 참고. 실제 FPS 변화는 측정이 필요합니다. |
| 드리프트 보정 버튼 | 보정 후 중앙 점을 1번 보면 화면 오프셋만 다시 맞춥니다. 오프셋이 0.2를 넘으면 거부하고 재보정을 안내합니다. | EyeLink 등 연구용 장비의 drift check/correction과 같은 방식입니다. 안경이 살짝 밀린 경우 전체 재보정 없이 맞출 수 있습니다. |
| 영역 표시 / `region` 출력 | 화면 상단 "영역 표시"를 켜면 현재 시선이 있는 칸을 강조합니다. 칸 경계에서 깜빡이지 않도록 0.04의 여유를 둡니다. `/api/status`에 `region: [열, 행]`이 추가됩니다. | 작품 화면에서 "어느 영역을 보고 있나"를 바로 쓸 수 있습니다. |

`--coarse` = `--mapping affine --validation region --grid 3x3 --bottom-row 0.8` + 1점 제외. 개별 옵션으로 덮어쓸 수 있습니다.

## 근거 1: 교수님 10/2 실제 기록

`diagnostics/20261002T071853Z-0058e7f6/summary.json`의 9점 동공 중심(320×240 기준)을 사용했습니다.
이 세션에는 독립 검증점 기록이 없어서 **한 점씩 빼고 나머지 8점으로 예측**했습니다. 가장자리는 외삽이라 오차가 실제보다 크게 나옵니다.

- 화면 0.1→0.9를 볼 때 동공 이동: **가로 56px, 세로 10px.** 세로 신호가 가로의 1/5입니다.

| 방식 | 한 점 생략 예측이 기준 안 | 평균 오차 (가로, 세로) | 9점 학습 통과 |
|---|---:|---|---|
| 기존: 2차 + 거리 0.12 | 1/9 | 0.120, 0.345 | 실패 |
| affine + 3×3 영역 | 4/9 | 0.085, 0.237 | 실패 |
| affine + 3×2 영역 | 5/9 | 0.085, 0.237 | **1점 제외 시 통과** |

**이 기록으로는 3×3이 통과하지 못합니다.** 세로 신호(10px)가 너무 작기 때문이며, 소프트웨어만으로는 한계가 있습니다.

## 근거 2: 시뮬레이션 (측정 아님)

위에서 잰 이동 범위(가로 56px, 세로 10px)를 쓰고, 점별 동공 중심 잡음을 1px 또는 2px로 둔 뒤 **1→9→4 전체가 통과할 확률**을 2,000번 반복해 구했습니다.
640×480은 "같은 움직임이 픽셀로 2배, 검출 잡음은 픽셀 단위로 그대로"라고 **가정**했습니다. 눈꺼풀 가림은 모델링하지 않아 아래 줄 위치는 결과에 영향이 없습니다.

| 캡처 | 점별 잡음 | 기존 (2차 + 0.12) | affine + 3×3 | affine + 3×2 |
|---|---|---:|---:|---:|
| 320×240 | 1px | 36% | 82% | 99% |
| 320×240 | 2px | 1% | 17% | 61% |
| 640×480 | 1px | 96% | 100% | 100% |
| 640×480 | 2px | 37% | 81% | 99% |

요약하면, **640×480 캡처와 3×2 영역 기준을 함께 쓸 때 잡음에 가장 강합니다.** 실제 잡음 크기는 현장 기록으로 확인해야 합니다.

재현: `python -m camera_accuracy.eval_coarse --output camera_accuracy/diagnostics/coarse/eval-20261004.json`

## 검사

- `camera_accuracy.test_coarse`: 6개 통과. affine 복원과 오프셋, 영역 허용 오차, 1점만 제외(2점 불량은 실패), 세로 신호가 약할 때 affine이 대부분 더 정확함, 영역 히스테리시스, 서버 전체 흐름(영역 검증 통과 → 드리프트 보정 → 영역 출력 → 큰 오프셋 거부).
- 기존 `test_accuracy` 15개(1개 skip)와 `test_verified` 4개 모두 통과.
- 영상 재생 모드로 화면을 띄워 오류 없이 로드되는 것과 `/api/plan`에 새 설정이 반영되는 것을 확인했습니다.

  2. `--engine deepvog-verified --coarse --grid 3x2`
